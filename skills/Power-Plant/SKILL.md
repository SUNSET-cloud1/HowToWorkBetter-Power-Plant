# ZM:PowerPlant —— 火电运检「如何活得更好」指南

## Overview

面向火电厂运行、检修一线人员的决策式工作指南。核心逻辑与《如何活得更好》一致：把每条建议按性价比排序，说清「花掉什么 / 换回什么 / 证据多硬」，让运检人员用最少时间精力判断「这件事该不该做、先做哪件」。

- **适用机组**：多种机组通用（125–1000MW，含亚临界汽包炉与超超临界直流炉）；机组差异明显处注明。
- **适用岗位**：集控运行与设备检修两者兼顾。
- **证据原则**：只引用权威来源（公开国标/行标/规程为主，内部规程与厂家文件为辅）；开源引用一律落可公开追溯来源。
- **费用与收益口径**：这里的「成本」不是钱，而是 **时间 / 操作风险 / 对机组负荷的影响 / 需协调的资源**；「收益」是 **设备可靠性提升 / 非停风险降低 / 工作效率提高 / 个人技能成长**。

## 目录框架

指南按场景分 6 章，每章 5–10 条具体建议，编号规则「章.条」（如 1.3）。完整目录（含每条的场景、成本、收益与证据提示）见 [references/framework.md](references/framework.md)，回答任何问题前必须读取。

| 章 | 场景 | 条目示例 |
|----|------|----------|
| 1 | 监盘与巡检 | 1.1 接班「三看」｜1.7 趋势看劣化 |
| 2 | 缺陷与消缺 | 2.1 缺陷三级分类｜2.5 消缺双确认 |
| 3 | 操作与调整 | 3.1 预演+唱票｜3.7 低负荷稳燃预案 |
| 4 | 检修与验收 | 4.1 按 DL/T 838 定修｜4.2 W/H 点见证 |
| 5 | 安全与应急 | 5.1 两票三制红线｜5.4 有限空间作业 |
| 6 | 学习与成长 | 6.2 事故错题本｜6.8 Anki 卡片化 |

## 条目模板

命中条目后，按以下 7 个字段完整展开，不得省略「成本」或「收益」：

```markdown
### [编号] [标题]
- **场景**：什么岗位、什么工况下适用
- **动作**：具体怎么做（可执行的步骤）
- **成本**：时间（…）｜风险（操作风险/对机组负荷的影响）｜资源（需协调的人/系统/备件）
- **收益**：可靠性/非停风险/效率/技能成长中，实际换回什么
- **证据等级及来源**：A/B/C ＋ 来源名称与章节/条款
- **说人话**：一句话告诉新人为什么要做
```

完整示例见 [references/examples.md](references/examples.md)。

## 证据等级

| 等级 | 含义 | 来源类型 | 引用方式 |
|------|------|----------|----------|
| A | 强制条款 | 强制性国标（GB）、《电力安全工作规程》、《防止电力生产事故的二十五项重点要求》、部委规章中的「应/必须」条款 | 直接引条文号 |
| B | 行业规程/厂家文件 | 推荐性标准（GB/T、DL/T）、行业导则、设备厂家技术文件、企业内部运行/检修规程 | 引章节，可结合现场调整 |
| C | 经验/论文 | 期刊论文、技术报告、行业经验总结 | 注明出处，需结合现场判断 |

## AI 调用逻辑

用户提出具体问题时，按以下顺序检索与回答：

1. **解析问题**：提取四要素——设备/系统（#1 机组？汽轮机轴承？）、现象/参数（瓦温缓慢上涨？振动超标？）、动作倾向（要不要停机？能否降负荷？）、岗位视角（运行处置 or 检修消缺）。
2. **查目录**：读取 [references/framework.md](references/framework.md)，用设备名、现象词、动作词做关键词匹配；一个现象可能命中多章多条，全部列出。
3. **排序**：
   - 先按风险紧迫度：第 5 章（安全与应急）→ 第 3 章（操作与调整）→ 第 1 章（监盘与巡检）→ 第 2 章（缺陷与消缺）→ 第 4 章（检修与验收）→ 第 6 章（学习与成长）。
   - 同优先级按性价比：成本低、收益高者在前。
   - 涉及「是否停机/降负荷」的问题，先给决策边界（何时必须停机），再给缓解性操作。
4. **命中**：按「条目模板」逐字段展开；证据从 [references/evidence-sources.md](references/evidence-sources.md) 选取并标注等级与来源；具体定值拿不准时标注「以本厂运行规程为准」，不编造条文号。
5. **未命中**：明确回答「指南未覆盖此条目」，随后给出最相近的条目编号与标题、建议的权威来源（本厂运行规程、厂家说明书、相关 DL/T），不编造结论。
6. **输出**：默认 Markdown，先结论后明细（做/不做/先做哪件＋一句话理由）；按用户需要可切换 HTML 网页、PDF、Anki 卡片。

## 支持形态

- **网页抓取**：需引用具体条文或核验最新标准时，用 web_fetch 抓官方来源（国家标准全文公开系统、国家能源局/发改委官网、行业网站）；优先官方域名；抓取失败则标注「待核验」，不编造。
- **PDF**：用户需要 PDF 时，先把内容写成 Markdown/HTML，再用 pdf skill 导出，保留引用来源。
- **Anki**：生成制表符分隔的 TSV/CSV（每行「正面\t背面」，正面=问题/定值/流程，背面=答案/来源），提示用 Anki 桌面端导入；不生成 .apkg 二进制。
- **图形界面**：用户需要图形界面时，生成自包含 HTML 指南页（搜索框、按章节筛选、条目展开/折叠），用 html skill 完成。

## 回答硬规则

- 每条建议必须完整 7 字段，不得省略成本或收益。
- 涉及人身安全的内容，先给安全结论再讲操作。
- 本厂定值/工况差异：标注「以本厂运行规程为准」。
- 证据等级为 C 的建议，必须注明出处并提示结合现场判断。
